# Tatsu: SwiftUI app for iOS, iPadOS and macOS

Date: 2026-09-28. Status: approved design, awaiting implementation plan.

## Goal

Ship Tatsu, the offline kanji lookup, on the App Store for iPhone, iPad and Mac from one Swift codebase. Version 1 does what the current Mac app does, plus a list of recent lookups.

## Decisions

| Topic | Decision |
|---|---|
| Audience | Public App Store. The developer account already exists. |
| App type | Native. Not a PWA. |
| UI | Rewritten in SwiftUI and shared by Mac, iPhone and iPad. The web UI is deleted. |
| Distribution | One App Store record covering iOS and macOS. `make_app.sh` is removed. |
| Price | Free. |
| Minimum OS | iOS 17, iPadOS 17, macOS 14. |
| Name | Store name "Tatsu – Offline Kanji", home-screen name "Tatsu", bundle ID `com.abbabon.kanji-offline`. |
| Language | English interface, with strings in a String Catalog so translation is possible later. |
| Network | None in version 1. Later packs download from GitHub Releases. |
| Privacy | "Data Not Collected". Recent lookups stay on the device and are not synced. |
| Data | KANJIDIC2, 10,384 kanji, bundled as `kanji.json` and loaded into memory. |
| Tap on a kanji | Opens the detail view. Copy is a button in the detail view, and also in the long-press / right-click menu. |
| Recent lookups | A kanji is added when its detail view opens or it is copied. Keep the last 100, newest first, with a Clear button. The list shows when the search box is empty. |
| Handwriting | Version 1 shows a hint on the "no results" screen to add the system Chinese handwriting keyboard. Built-in recognition is a later pack. |

## Scope of version 1

In:
- Search with the same inputs and ranking as today: English, hiragana, katakana, romaji, text containing kanji, and one-typo tolerance.
- Detail view: kanji, on and kun readings with kana and romaji, meanings, stroke count, school grade, JLPT level, frequency rank, Copy.
- Recent lookups.
- iPad and Mac split layout.
- About screen with the KANJIDIC2 credit and a CC BY-SA 4.0 link.

Out: action extension, camera, data packs, handwriting recognition, syncing, translations. See the roadmap below.

## Repo layout

```

Tatsu/

  Kanji.swift            Codable model; loads kanji.json from the bundle
  Search.swift           port of search.js: kana to romaji, normalisation, scoring
  SearchView.swift       search field + results; empty state = recent lookups + handwriting hint
  KanjiDetail.swift      readings, meanings, stats, Copy
  AboutView.swift        KANJIDIC2 attribution and license link
  Recent.swift           SwiftData model: kanji character + last opened date
  kanji.json             generated by build_data.py, committed
  Assets.xcassets        AppIcon: one 1024 px PNG rendered from logo.svg, full bleed, no transparency
  Localizable.xcstrings  String Catalog
  PrivacyInfo.xcprivacy  no tracking, no collected data
TatsuTests/
  SearchTests.swift      every case from test.js, plus a check that kanji.json decodes to 10,384 entries

```

Deleted: `index.html`, `search.js`, `data.js`, `test.js`, `main.swift`, `make_app.sh`.
Kept: `logo.svg`, `logo.png`, `LICENSE`, `README.md` (rewritten for the App Store version).

There is no separate Swift package in version 1. The search code moves into a shared package in version 1.1, when the action extension needs it.

## Data flow

1. `build_data.py` downloads KANJIDIC2 and writes `Tatsu/kanji.json`. The file is committed, so building the app never needs the network.
2. At launch the app decodes `kanji.json` off the main thread into `[Kanji]`.
3. On every keystroke, `Search` scores all entries and returns them sorted. The ranking order is exact match, then prefix, then whole word, then substring, then one edit away, then scattered letters. Ties go to the more frequent kanji. Input containing kanji returns each kanji of the input, in order.
4. Opening a detail view or copying a kanji inserts or updates its `Recent` row. Rows beyond the newest 100 are deleted.
5. Clear deletes all `Recent` rows.

## Interface

- `NavigationSplitView`: results in the sidebar and detail on the right on Mac and iPad. On iPhone it collapses to a list that pushes the detail screen.
- Search field: `.searchable`, with auto-capitalisation and autocorrect off.
- Mac keys: Cmd+F focuses the search field, Esc clears it, and typing while the field is not focused sends the text to the field.
- Furigana: SwiftUI has no ruby text, so each reading is drawn as a small vertical stack with kana above and romaji below.
- Dark mode follows the system.

## Error handling

- The only failure in version 1 is `kanji.json` missing or failing to decode. That is a build error, not a runtime state, so the app stops with a clear message. The decode test in `SearchTests` catches it before release.
- An empty search result shows "No matches" and the handwriting keyboard hint.

## Testing

- `SearchTests` ports every assertion in `test.js` (romaji conversion and ranking) and adds the `kanji.json` decode check. Run with `xcodebuild test`.
- Manual checks on an iPhone, an iPad (or simulator) and a Mac:
  - searches for `water`, `watr`, `mountian`, `みず`, `ミズ`, `taberu`, `日本語`
  - Copy
  - Recent and Clear
  - dark mode
  - rotation
  - Cmd+F and Esc on Mac

## Release

1. Work on the `swiftui` branch and merge to `main` when version 1 passes the tests and manual checks.
2. Reserve the name in App Store Connect. If "Tatsu – Offline Kanji" is taken, choose a new name before submitting.
3. TestFlight on iOS and Mac.
4. Submit both platforms together.

## Roadmap after version 1

| Version | Feature | Notes |
|---|---|---|
| 1.1 | Action extension, "Look up in Tatsu" | Also works from the Mac share menu. The search code moves into a shared Swift package used by the app and the extension. The extension has a tight memory limit, so it loads only the kanji data. |
| 1.2 | Camera lookup | VisionKit `DataScannerViewController` with Japanese Live Text. iPhone and iPad only. |
| Pack | Stroke order | KanjiVG (CC BY-SA 3.0). Shown in the detail view. |
| Pack | Words and compounds | JMdict, stored as SQLite with full-text search. |
| Pack | Radicals and components | KRADFILE. |
| Pack | Handwriting recognition | Core ML model trained on KanjiVG stroke data. Replaces the keyboard hint. |

Packs are optional downloads from GitHub Releases, managed from a Packs screen with install and remove. Each pack carries its own license credit on the About screen. Packs are free.
